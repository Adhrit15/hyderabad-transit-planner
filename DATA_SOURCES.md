# Data sources

Everything in `backend/src/main/resources/data/` is generated by `node tools/generate-data.mjs`.
The frontend uses a copy of the same files.

| Data | Status | Source / method |
|---|---|---|
| Station names and order (Red 27, Blue 23, Green 9) | **Verified** against public line lists | [Red Line (Wikipedia)](https://en.wikipedia.org/wiki/Red_Line_(Hyderabad_Metro)), [Blue Line (Wikipedia)](https://en.wikipedia.org/wiki/Blue_Line_(Hyderabad_Metro)), [themetrorailguy.com](https://themetrorailguy.com/hyderabad-metro-information-map-updates/) |
| Line lengths (Red 29.2 km, Blue 27 km, Green ~11 km) | **Verified, but sources disagree** (Green is quoted as 9.6–11 km) | Same sources as above |
| End-to-end time, Blue ≈ 48 min | Verified (blog/press figure) | [housing.com Blue Line guide](https://housing.com/news/hyderabad-metro-blue-line-route-stations-map/) |
| Fares (₹11–₹69, 10 distance slabs, effective 24 May 2025) | **Verified** from several press reports of the HMRL chart | [Telangana Today](https://telanganatoday.com/hyderabad-metro-rail-announces-revised-fare-chart-with-10-per-cent-discount), [The News Minute](https://www.thenewsminute.com/telangana/hyderabad-metro-announces-10-discount-on-increased-fares), [Siasat (pre-discount chart)](https://www.siasat.com/hyderabad-metro-fares-revised-new-rates-effective-from-may-17-3221038/), [L&T Metro fare chart PDF](https://ltmetro.com/wp-content/uploads/2025/05/Hyderabad-Metro-Rail-Revised-Fare-Chart-Final.pdf) |
| Station latitude/longitude | **APPROXIMATE** (`"approximate": true` on every station) | Hand-estimated from map knowledge, probably within ~200–400 m. Not checked against a survey source. |
| Per-segment km | **APPROXIMATE** (derived) | Straight-line distance between the approximate coordinates, scaled so that each line's total matches its published length |
| Per-segment minutes | **APPROXIMATE** (derived) | `km / 40 km/h × 60 + 0.3 min dwell`, calibrated to end-to-end figures (Red ≈ 52 min, Blue ≈ 48 min) |
| Transfer cost (5 min) | **Assumption** (configurable) | Walking between platforms plus average wait; not measured |
| Max train speed (80 km/h, used by the A* heuristic) | Assumption, matching the commonly quoted design speed of the rolling stock | Only an upper bound on speed matters for admissibility |

## Modelling simplifications
* **Parade Ground** (Blue) and **JBS Parade Ground** (Green) are physically separate stations
  joined by a skywalk. They are modelled as a single interchange station, and the walk is
  included in the 5-minute transfer cost.
* **Fares:** HMRL charges a fixed fare per station pair, based on the shortest distance. This
  project charges by the distance *actually travelled*. Without that change, the "cheapest" mode
  would always match "shortest distance" and teach nothing. See REPORT.md §5.
* The Green Line extension to Falaknuma and the Phase-2 corridors are not included. They were
  not operational at the time of writing.

# Phase 2: multimodal planner data

The registry is [pipeline/sources.json](pipeline/sources.json). Its live state (freshness, counts,
warnings, overrides) is published with every build as `data/status.json` and shown in the app under
**Data sources and freshness**. A history of data changes is kept in
[pipeline/state/CHANGELOG.md](pipeline/state/CHANGELOG.md).

**Download note:** OpenCity (`data.opencity.in`) hosts the same feeds but sits behind a bot
challenge, so the pipeline uses the Mobility Database mirror (`files.mobilitydatabase.org`), which
allows automated downloads. To add a mirror, append its URL to the source's `urls` array.
